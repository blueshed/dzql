# CLAUDE.md

Bun only — never `node`, `npm`, or `yarn`. Run tests with `bun test --coverage`, aiming for 100%. Verify every bug fix by reverting it, confirming the new test fails, then restoring it.

## Architecture

eta is a kernel plus examples. `src/` is the generic kernel: it has no idea "chat" exists, and never imports anything under `examples/`. Each `examples/<name>/` is a complete, self-contained app built on the kernel; adding a new one (e.g. `examples/wedding/`) never requires editing anything in `src/`.

- Kernel: `migrations/0001_ledger.sql` → `src/ledger.ts` (records every patch + inverse; `nextUndo` derives undo's cursor from it, no separate state) → `src/concepts/concept.ts` (the `Concept` contract: `render?`/`resolveDoc`/`permit`/`write`/`replay?`/`onOpen?`/`onClose?`; concepts talk to each other only through `src/concepts/bus.ts` events, never by importing each other's internals) → `src/concepts/index.ts`'s `assemble(example)` (wires one example's concepts together, appending the kernel's own ledger concept) → `src/server.ts`'s `createServer(example, port?)` (generic `{doc, ops}` dispatcher; no per-feature branches) → `src/client/` (browser: `app.ts` forwards `data-write` gestures and morphs renders via `morph.ts`; it knows nothing about any specific applet -- an example registers its own).
- An example (`examples/<name>/`): its own `migrations/*.sql` (applied under its own namespace, see below) → its own `documents/*.ts` (SQL read/write against its own `db.ts`; `patch()` is the only write path, computing each op's inverse) → its own `concepts/*.ts` (the same `Concept` contract as the kernel's) → its own `applets/*.ts` (client-side components, registered into the kernel's `src/applets.ts` registry) → its own `client/` (an `index.html` that loads a `main.ts` which registers the example's applets, then imports the kernel's `src/client/app`) → `index.ts`, which exports `example: Example` -- the one thing the kernel needs to run it.
- `src/example.ts`'s `Example` type is the seam: `{ name, concepts, active(sessionId), index, routes? }`. `concepts` is the example's own render order (the kernel appends its ledger concept after them); `active(sessionId)` is the "may this session write at all right now" guard every write path needs (a stale, logged-out tab shouldn't be able to undo a write made before it went stale) -- the kernel can't derive this generically, so it asks the example; `index` is the page (a Bun `HTMLBundle`); `routes` are optional extra HTTP routes (a kernel route of the same path always wins).
- Undo is a `Concept.replay?(ws, docId, ops, undoes)` method: applies already-shaped ops (a ledger inverse) to a document and echoes exactly as a direct write would, skipping `permit` (this isn't a fresh request against the normal writable surface). The kernel's ledger concept (`src/concepts/ledger.ts`, a factory: `createLedgerConcept(lookup, active)`) finds `nextUndo(sessionId)`, splits its `doc` into `{docType, docId}`, and calls `lookup(docType)!.replay(ws, docId, entry.inverse, entry.id)` -- no example-specific dispatch, no cross-concept event needed for it.
- Migrations are namespaced: `migrate(db, dir, namespace)` records each applied file as `${namespace}/${file}` in `_migrations`, so the kernel's own migrations (namespace `"eta"`) and an example's (its own `name`) can't collide on filename. An example's `db.ts` imports the kernel's `db` from `../../src/db`, runs its own migrations under its own namespace, and re-exports it -- every document module in that example imports `db` from its own `./db`, never from `src/db` directly, so its migrations are guaranteed to have run before its prepared statements (created at module load) touch the database.
- `src/start.ts` resolves which example to run from `ETA_EXAMPLE` (default `chat`); `src/cli.ts` loads that example's own `cli.ts` (an alias table of short verbs, e.g. chat's `name`/`room`/`send`) if it exists, alongside the kernel's own generic `inspect`/`watch`/`undo`/`write <doc> <op> <path> [value]` commands.

## Rules from the change request that shaped this

- HTML is the only vocabulary. No node/JSON tree on the wire or in the client.
- A write names a document and a JSON Pointer path — never a function name.
- No client-side domain state beyond the small op-log in `window.eta.docs()`.
- The client morphs (`morph.ts`) instead of replacing `innerHTML`; `[data-applet]` elements are a boundary the morph never descends into.
- No new dependencies without asking first.

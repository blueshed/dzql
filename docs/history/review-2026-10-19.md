## DRY / YAGNI / KISS review of bluetools (19 October, read only, against HEAD a75acb01)

Six reviewers (railroad+delta, dzql Postgres side, dzql rendering+modelling, dzql examples+create-dzql,
paintbrush+create-blueshed, root) read the repository; the leading findings were re-checked by hand
(the lines quoted were opened). Uncommitted work in dzql/src/modelling and examples/cafe/model was
read at HEAD. The full report is the session's final message; this file is the same list.

### Top findings (verified)

1. KISS/bug: scripts/affected.ts:64-72 splits dzql into eta/pg halves wrongly. src/cli (imports modelling,
   rendering) is in the pg half, so a src/cli change runs only tests/compile; examples/cafe and starter
   import dzql/postgres, so a src/postgres change never runs them. Same split in dzql-eta.yml,
   dzql-postgres.yml, bunfig.toml coverage exclude. Delete the split: dzql always runs test:fast (26s).
2. KISS: harness.ts:1 imports rendering/db, which opens db.sqlite at import. `dzql/modelling` (the
   barrel the README tells people to use) and `dzql/rendering/test-socket` (imports modelling/harness)
   create db.sqlite in cwd. Open lazily in sqliteStore; move hear/applyOp to resources/render.ts.
3. KISS/bug: two app shapes (index.ts `example` vs routes.ts `app`). appIn knows both, but start.ts:5 and
   `dzql serve` (cli/model.ts:180) import index.ts only, so `dzql serve` fails in every create-dzql app.
   Nothing runs `dzql serve`: delete it now; move the five old examples to routes.ts later.
4. DRY: workflow path filters hand-copy the dependency graph and have drifted (paintbrush.yml watches
   only dzql/src/modelling but imports dzql/rendering/*; railroad/delta omit tsconfig.json;
   delta-railroad.yml's 5-file list). publish.yml:60-68 gates create-dzql on dzql-postgres and never
   runs create-dzql's own test. One workflow running affected.ts --slow (needs --base).
5. YAGNI/bug: a new paintbrush app keeps "name": "paintbrush", the bun-create postinstall entry,
   and "test:slow": "bun run test:evolve" with test:evolve removed (broken script); tsconfig includes
   missing "scripts". Old `bun create blueshed/paintbrush` scaffolding (commitEverything retries,
   packages/paintbrush/.github/workflows/ci.yml which GitHub never reads, regexes stripping it).
6. DRY/YAGNI: examples/modeling/loader/model/ is 1656 lines of vendored hjeli, a second
   implementation of closure.ts's six checks, used only by model:check and --against; ships on npm.
7. DRY: src/compile per-document dispatcher written 7 times; empty CASE handled 3 ways (two local
   dispatch(), ternaries, codegen noEmptyCases regex); lit twice (postgres/sql.ts:9, compile/opens.ts:21).
8. DRY/YAGNI: postgres/schema.ts validateOps is a third copy of write rules (delta validate.ts, SQL
   001a), drifted (error path), no runtime caller.
9. DRY: harness copies the client's control rules (form-value.ts pressed/drawnOption/sends) twice,
   by-hand's PAGE a third time; the "can it be pressed" rule in 3 code places + 4 prose places.
10. DRY: dzql/examples/delta/sites-bbox schema + README and tests/delta-pg/helpers/examples.ts copied
    from delta (already drifted: PID_FILE). The publish-to-subscribers stand-in written ~10 times.
11. DRY: delta's server.ts usage header and evals/delta-doc.json:14 teach a hand-written Bun.serve,
    against the one-server rule.
12. DRY: railroad's webview.ts header vs bun-route/reference/webview.md disagree; tests/webview.test.ts
    ignores the kit (own waitFor using Date.now).
13. YAGNI: docs/plan.md lines ~13-154 stale (versions, paths, #14), and dzql CLAUDE.md lists it as
    read-first; docs/client-plan.md finished, its one open item tracked nowhere.
14. DRY: delta CLAUDE.md file map drifted (fan-out in sqlite/write.ts, migrate refuses postgres://).
15. YAGNI: exports nothing imports: modelling/definitions, rendering/cli (runs on import),
    barrels doc-only; postgres re-exports of delta auth; GenerateSqlOptions + daily `Generated:` date.

Small mechanical list: see the final message.

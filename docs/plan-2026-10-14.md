# The ten medium items, 14 Oct 2026

Each item starts with a story: a person's intent, in a sentence a customer could call true or
false. Write it in the example's `stories.ts` (or, for tooling, as a test that names it), watch it
fail, then build the least that makes it pass. Peter's word: fix them all, then publish.

The detail of each is its entry in `todo.jsonl` (`n<number>`).

## A. The field you are typing in (n4) and what is announced (n45)

- **n4, narrowed.** Rows are addressed by id and every page is told every change, so a write never
  lands on the wrong row and nobody reads a stale page. What is left: the morph keeps the field
  you are typing in (`src/client/morph.ts`), so a change from someone else to that field is not
  seen, and your next keystroke writes over it. Story (leave or the wedding, whichever has a free
  text field two people can change): *"Ann is changing the note when Ben changes it too; Ann is
  told Ben changed it, and her next keystroke does not write over his unseen."* RFC 6902's `test`
  op (the value the field was drawn with) is the likely shape; a refused write shows the new value.
- **n45.** *"Ada's connection drops, and she hears that it is reconnecting."* The offline note is
  HTML in a `role="status"` region, not CSS `::before` content. Changes from others stay silent,
  decided and written down: the bento says a change speaks to the person who made it.

## B. Paging (n3)

Chat. *"Ada scrolls back past the first fifty messages and reads what Bob said yesterday."* and
*"Bob speaks while Ada is reading old messages, and her place does not move."* A keyset window
(`before=<id>`), never an offset; its readers told when the base document changes.

## C. Who you are, before the socket opens (n8)

Leave. The seam is `Example.identify(req)` at `/ws`, before the upgrade: a session id to use, or a
Response that refuses. *"A request from the trusted proxy naming Ann opens on Ann's desk, with no
sign-in."* and *"The CLI signs in as Ann with a token and reads her desk."* and *"Someone who keeps
guessing Ann's password is slowed down."* OAuth2 and LDAP sit behind the same route shape; no new
dependency without asking Peter.

## D. A page drawn from a document's shape (n2)

The wedding. *"The couple add a venue, and it is in the list"* -- with no view written for venues.
Derive at render time, never generate files; derive from what the document declares, never from an
entity; a type may name an applet, so an override is a registration, not an edit to every view.
Write down where the override ladder stops. Keep it small: the kernel is as small as it can be.

## E. A write nobody offers (n32)

The harness. *"A compartment that permits a write no story tells and no page offers is named by
`bun run stories`."* Probe each document's paths with the cast's writes the stories and pages never
make; any that is permitted is a hidden verb, reported as a warning.

## F. The client in the coverage gate (n15), and its size (n102)

- **n15.** *"A builder breaks the client's morph, and `bun test` fails the coverage gate."* Collect
  coverage of `src/client/*`, `src/applets.ts`, `src/island.ts` and the applets. A new dependency
  (happy-dom) needs Peter's yes: stop and say so.
- **n102.** *"Chat's page reaches a phone in fewer bytes than at 0.51.0."* Measure with
  `bun run costs`; trim only what weakens nothing; the railroad change (`DEV` folded in production)
  is written as a patch for railroad, not published.

## G. The toolset (n23, n21)

- **n23.** *"A builder opens eta in a fresh Claude Code web session, and `bun test` is green."* A
  Bun-only SessionStart hook in eta (`bunx`, `bun -e`; progress to stderr; a guarded env file) that
  stages Chromium when a test uses `Bun.WebView`, and does nothing on a Mac.
- **n21.** *"A builder asks Claude for a live multi-user app in an empty folder, and Claude chooses
  eta, delta or railroad by one guide."* Drafted as a local `blueshed` plugin folder beside the repos,
  with its router skill; nothing published, delta's and railroad's repos not touched.

## How the team works

One teammate per letter, each in its own worktree. Each loads the eta-app skill first, writes its
stories first, and ends green: `bun check`, `bun test`, `bun run stories:all`, `bun run costs
--check`. A bug fix is verified by reverting it and watching its test fail. Teammates leave
`CHANGELOG.md` and `todo.jsonl` alone and report their changelog lines; the merge writes them. Then
`/publish`.

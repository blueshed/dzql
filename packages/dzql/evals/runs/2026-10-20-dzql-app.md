## Findings

1. **Page: `reference/where-an-app-lives.md` (starting from an example), and the examples'
   `client/styles.css`. The examples are still not portable.** This is round 1's finding 6, and it
   cost scenario 2 most of its run.
   - leave, chat, ticker and wedding import `../../../src/rendering/bento.css`; only the cafe uses
     `dzql/rendering/bento.css`.
   - leave's `upgrade.test.ts` spawns `src/modelling/stories-run.ts` from `../..`.
   - The template's `tests/routes.test.ts` and its empty root `stories.ts` stay beside a copied
     app.
   - Fix: import by package path in every example. Then either say in where-an-app-lives.md what
     to replace when an example becomes `src/`, or have the eval's copy step replace the template's
     tests and stories.
2. **Page: `reference/stories.md`. Say what the harness does with Undo.** This is round 1's
   finding 2. It should say three things:
   - Every `does` story is undone and redone, and every page is compared back. So an Undo feature
     needs only `undone` and `redone` lines, plus a `cannot` story where a walk is refused (nothing
     of yours to take back, or another's later change in the way).
   - An undo as a write is `{ doc: "ledger", ops: [{ op: "remove", path: "/latest" }] }`
     (`walked("undo")`, `dzql/rendering/json-patch`).
   - What `premise` does, with an example.

   Session 3 read `src/modelling/stories.ts:40-140` and `harness.ts` for all three.
3. **Page: `reference/stories.md` (and SKILL step 1). "Watch it fail" should mean on the story's
   own terms.** This is round 1's finding 3.
   - A load error (`Cannot find module './src/links'`) is not a failing story.
   - Say: build what the story file imports (`links.ts`) first, or stub it, so that the first red
     is a story's.
   - Extend "let the write through for a moment" beyond `cannot` stories to any story that passes
     before it is built, `opensTab` included.
4. **Page: `reference/documents.md`. Show `prepare`.** This is round 1's finding 4. SKILL step 2
   names `prepare` to seed the store, and documents.md says "Seed only into empty tables", but no
   page shows `openStore({ ..., prepare: async (pool) => { if empty: importTables(pool, schema,
   { tables }) } })`. Session 1 grepped `postgres/app-store.ts` for it, in both rounds.
5. **Pages: `reference/resource.md` and `reference/refusal.md`. Show the split in `permit`.** This
   is round 1's finding 5.
   - Two sessions, in two rounds, threw `refuse(words)` from `permit` for a person with no control.
   - refusal.md says a plain `false` is right there.
   - resource.md's `permit` example should show both: `false` for the role that has no control,
     and `refuse` only where a control sent the write.
6. **Page: `reference/bento.md`. Say how Undo follows the role.** This is round 1's finding 8,
   answered by the harness rather than a page.
   - With `undo: true`, a person with nothing on the ledger gets a control that always fails, and
     the stories refuse it.
   - Session 3 found this only by failing twice. Its answer was two `bento()`s, chosen by role
     (`surfacesFor(role)`).
   - bento.md should say that this is the way, or name the seam meant for it.
7. **Eval file, `evals/dzql-app.json`. Two lines still contradict the skill.** Neither was changed
   since round 1.
   - Scenario 1, line 2 puts "its schema" in `visitors-api.ts`. SKILL step 2 puts the tables in
     `store.ts`. documents.md now also allows a schema per resource, in its `-api.ts`, through
     `openStore({ schema: [a.schema, b.schema] })`.

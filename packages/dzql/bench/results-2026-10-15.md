# Bench results: 2026-10-15 (dzql, after 2c's holds and write scope)

3,000 single-field updates per adapter, 200 warm-up iterations discarded, every write as
`bench_app` (NOSUPERUSER NOBYPASSRLS) under the policy. Loopback Postgres 16 (the test compose on
`localhost:5433`), pg Pool (max=4), macOS / Apple Silicon.

```
                        p50         p95         p99        mean       total    RTT
raw-postgres           0.184 ms     0.239 ms     0.307 ms     0.189 ms      0.57 s     1
delta, framework       1.078 ms     1.179 ms     1.416 ms     1.100 ms      3.30 s     1
delta, compiled        0.839 ms     0.919 ms     0.992 ms     0.860 ms      2.58 s     1

delta, framework / raw-postgres p50: 5.87x
delta, compiled  / raw-postgres p50: 4.57x
compiled / framework p50:            0.78x
```

Compiling who holds a row and a write's scope took 22% off a write. The rest of delta's cost over
a raw `UPDATE` is `delta_apply` itself (the op walk, validation, the inverse, the fan-out's telling),
still read from the definitions at run time: the next pieces of 2c.

Fan-out, one write through `fanout:1` with 10 open, as the names ever opened grow (admin role):

```
    ever opened         p50         p95        mean    writes
             10     1.010 ms     1.176 ms     1.028 ms       500
          1,000     0.953 ms     1.081 ms     0.972 ms       500
        100,000     1.237 ms     1.363 ms     1.268 ms       500
```

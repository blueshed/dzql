## Findings

1. **The harness, not a skill: a railroad start leaks railroad's devDependencies.** `make()` writes
   `"@blueshed/railroad": "file:<checkout>"` and runs `bun install`. Bun installs a `file:` folder's
   devDependencies (`@types/bun`, `@happy-dom/global-registrator`, as `bun.lock:16` records) at the
   project's top level. `shipped()` then swaps the package for the tarball but leaves those
   behind. Railroad #1 and #3 wrote `types: ["bun"]` and a happy-dom preload, but their
   `package.json` lists neither package. On a packed-only install of the same files, `bun check`
   fails with TS2688 and the tests fail with "Cannot find module '@happy-dom/global-registrator'".
   A person who runs `bun add @blueshed/railroad` would hit both. Fix: install the tarball itself
   (`bun add <tgz>`), not the `file:` folder, so the start has only what npm would bring. Then the
   scenarios can see whether a session adds these.
   - **Skill, `railroad/reference/testing.md`:** it shows `happy-dom.setup.ts` importing
     `@happy-dom/global-registrator`, but never says to install it
     (`bun add -d @happy-dom/global-registrator`). The leak hid that gap in both runs.
   - **Skill, `railroad/reference/setup.md:65`:** it already says `@types/bun` is needed. Railroad
     #1 and #3 skipped it only because the type check already passed.
2. **The harness: `bunfig.toml`, and "no tests".** The fallback to a project's test script helps
   only when a session writes one. Railroad #3 did not, so the run records 2 failures that are the
   harness's. Either let these sessions write `bunfig.toml` (a permission rule for the file in the
   project's settings, if Claude Code honours one for a sensitive file, or a Bash-only route the
   page could name), or have the harness retry with `--preload ./happy-dom.setup.ts` when that file
   exists. Separately, `results.json` still records "0 test files" as `exit: 1` (bun-route #2); it
   should record no tests.
3. **No line missed this round.** Every scenario line held, so the scenarios no longer separate a
   good skill from a better one. Each trap they aim at is now answered by a page, word for word in
   places (finding 6). The next round needs scenarios aimed at what is still untested: a
   collection filtered or sorted through `.map()`, which costs the whole array; `at(id)` for a
   detail view; a delta app's `serve(app, { port: 0 })`; tsx-react mode.
4. **`railroad/reference/setup.md`'s `server.ts` has no `port` and no `Listening on` line**
   (`setup.md:48-56`), and the railroad skill never points to bun-route's "Checking a route".
   Railroad #3, which read only railroad pages, wrote `serve(port = 3000)`, ignored the
   harness's `PORT`, logged `listening on` in lowercase, and curled the fixed port. Give the
   snippet `port: process.env.PORT || 3000` and `console.log(\`Listening on ${server.url}\`)`, as
   `bun-route/reference/server.md:13-27` has, and add one line linking to
   `server.md#checking-a-route`.
5. **`bun-route/reference/webview.md:56` names `src/webview.ts`.** That is the checkout's layout.
   The npm 0.17.0 that the empty starts install is flat (`webview.ts` at the root). bun-route #1 and
   #3 each failed once on that path. It settles itself at the next release; until then, "the
   header of `webview.ts` in the package" is right for both.
6. **`bun-route/reference/webview.md`'s skeleton is bun-route #3's answer.** The skeleton uses the
   scenario's `#name`, `#submit`, `"Ada"` and `"Hello, Ada"`, and bun-route #3 copied it with one
   selector renamed. Change the skeleton's page (say, a counter or a todo item) or the
   scenario's (another form, a different disabled control), so the line measures applying the
   rule, not copying it.
7. **`railroad/reference/realtime.md:42` has the cost, but a session still checks the source.**
   Railroad #1 read the paragraph and then grepped `collection`'s implementation. This is less of
   a detour than round 2's `sed -n 923,1120p`, and the code is right either way. If the author
   wants the trip gone, `SKILL.md` "What bites" 9 could say "the cost is in realtime"; otherwise
   this can be left. The log's "lookup by key" against the page's "`indexOf`" suggests the
   session never took in that sentence.
8. **No scenario line is wrong, and none contradicts a page.** bun-route #2's query says "package.json
   has no dependencies" while the fixture has `devDependencies: @types/bun`. That is true as worded,
   and the session read it so.

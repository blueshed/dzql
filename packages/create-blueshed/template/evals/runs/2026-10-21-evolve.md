## Findings

1. **migrations.md's `up` is wrong on a temporal table, and loses or adds to people's orders.** This is high severity.
   - **Why:** `001-order` makes `lines` temporal, with primary key `(id, valid_from)`, and a line taken off keeps its row with `valid_to` set. The page's `count(*)` and `min(id)` read every version, so a Tea taken off is counted back on, and `DELETE FROM lines WHERE id <> first` erases the history the table keeps.
   - **Proof:** I ran the page's two statements on a scratch table. Order 3, with one live Tea and one taken off, became `Tea ×2`, and its closed row was gone.
   - **Why the gate misses it:** `tests/evolve.ts` and the fixture pass only because their data has no closed versions.
   - **The session's `up`:** it counts and keeps only `valid_to IS NULL`, then closes the others with `UPDATE ... SET valid_to = ?`. That is how delta closes a row itself (`server/sqlite/rows.ts:52`). It is the one to put on the page, with a removed line in its test.
   - **Page:** `evolve/references/migrations.md`, its `up`, its test, and a line saying an `up` on a temporal table reads and writes only live versions and closes rather than deletes.
   - **Scenario:** the fixture's `data/app.db` should hold a line taken off, so this trap is in the scenario. Line 1 should say "folds an order's live lines, closing the rest".
2. **migrations.md says "the page and its tests are as they were (a line added is quantity 1)", but then the next Add of a tea makes a second line, which is what the query says must not happen.**
   - The session changed Add to count on the item's line and × to take one off, and its tests pass.
   - **Page:** `migrations.md` should show the view's Add and × after the count.
   - **Scenario:** line 4 is wrong. It should read "Leaves the documents as they were: the order, kitchen and Undo tests pass unchanged, and Add counts on the item's line".
3. **Counting on the page is a read, then a write, and two windows race.** This is the API trap, an item for Peter.
   - This is the session's todo #1. Add sends `replace quantity = n + 1` from the page's copy, so two windows pressing at once lose a count. Two first Adds also make two lines; the session queued one window's presses to dodge this.
   - delta's three verbs have no "one more", and the only fix today is a unique key on live `(orders_id, item)` or a server write.
   - Per the repo's rule, that is an API change, not more words in the skill. No evolve page would prevent it until delta answers.
4. **document.md and two-documents.md drop `.persisted`.**
   - Their `routes.ts` block is `await notesDoc(ws, dataDir);` and `await orderDocs(ws, dataDir);`. The message's line is `closing.push((await messageDoc(ws, dataDir)).persisted)`, and the JSON engine saves asynchronously (`json.ts`, its `saving` chain). So a server stopping may not wait for the last note or order to reach the file.
   - Scenario 1 copied it, and scenario 2 fixed it on its own.
   - sqlite.md has the same gap: it opens a `Database` and never pushes its close, though `routes.ts` says a resource that opens a database pushes its close onto `closing`.
   - **Pages:** `document.md`, `two-documents.md`, `sqlite.md`. No scenario line covers it.
5. **two-documents.md hard-codes `order:1`, so every customer shares one order.**
   - Scenario 2 built that and made it its first, highest question.
   - **Page:** `two-documents.md` should say the one order is a stand-in, and how a customer gets their own: a "New order" modal that puts its id where you are, or `auth.md`.
   - **Scenario:** line 2 says "the customer's order" and could ask for this once the page shows it.
6. **http.md has no view for an upload.** Scenario 3 put a raw file input in the cell's body, which breaks the bento's "made in a modal".
   - **Page:** `http.md` should add the view: an upload in a modal if the bento's `addModal` can take a file, else say an upload is the cell's own. This is minor.
7. **sqlite.md's Undo browser test checks the order through its document, not the Your order cell.** Scenario 2 copied it. The test would be stronger if it also waited on the cell.
   - **Page:** `sqlite.md`. This is minor.
